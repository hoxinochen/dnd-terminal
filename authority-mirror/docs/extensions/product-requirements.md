## 唯一职责

本文件保存长期产品意图与 `v0.1.0` 用户可观察需求。ABC 负责决定本次实际施工子集；Architecture 负责已批准的数据与技术边界；Rules Baseline 负责规则证据。

## 产品目标

`DND Terminal` 应让 DM 在一个共享战斗会话中：

1. 从角色、怪物或 NPC 模板创建独立单位实例；
2. 管理先攻、轮次、回合、动作经济和移动；
3. 在二维方格地图上放置、移动和高亮多格棋子；
4. 跨标签页同步 HP、临时 HP、资源、法术位、状态和位置；
5. 放置可拖动的二维范围模板并识别候选目标；
6. 经 DM 确认后批量应用伤害、治疗、Buff 或状态；
7. 以可读、可导出、可撤销但不可无痕改写的事件记录保留历史；
8. 自动保存、刷新恢复、JSON 导出与重新导入；
9. 结束战斗时由 DM 审核角色卡差异并选择性回写。

## 标签页

所有标签页操作同一个权威战斗会话。显示设置不是数据所有权。

| Tab | Primary Responsibility |
|---|---|
| 战斗 | 先攻、当前行动者、轮次、行动经济、单位概要 |
| 地图 | 方格、棋子、路径、距离、高度、范围模板、当前行动者高亮 |
| 角色 | 玩家角色长期卡片的只读基线与战斗差异视图 |
| 单位库 | 玩家、NPC、怪物模板与实例创建 |
| 日志 | 操作、人工修正、撤销、可读战报与结构化导出 |
| 掷骰 | 公骰、暗骰、常用骰式与受限自动化 |
| 设置 | 标签显示、地图尺寸、每格距离与距离口径 |

关闭标签页不得删除数据、停止状态维护或停止日志记录。

## 地图与棋子

- `v0.1.0` 只实现二维空白方格地图，不实现美术地图、3D 或六角格。
- 地图尺寸可配置；默认每格 5 尺。
- 支持鼠标与触屏。
- 棋子可选中、拖动和高亮；当前行动者与行动轮同步高亮。
- 移动提交后记录起点、终点、路径、规则计算距离、实际扣除移动力与高度变化。
- 高度只作为数值与提示，不参与三维命中、视线或范围断言。
- 大型、巨型与超巨型单位使用多格占位。
- 同一模板可生成多个彼此独立的实例。
- 不自动判定墙体、碰撞、完整视线、遮挡或掩护。

## 范围模板

范围模板是独立地图层，至少支持：

- 圆形：按下位置为中心；
- 锥形：通常以施法者为源点，拖动决定方向；
- 直线：通常以施法者为源点，拖动决定方向；
- 方形：由能力定义决定中心或锚点；固定测试使用“中心点”；
- 自身范围：固定关联施法者；
- 自由放置：由 DM 显式启用。

交互顺序必须为：

```text
选择能力
→ 放置并拖动范围
→ 实时预览覆盖格与候选单位
→ 松开后保留预览
→ DM 手动增删边缘目标
→ DM 确认
→ 执行批量变更
→ 写入目标、结果与覆盖信息
```

预览本身不修改战斗状态。墙体、掩护、视线和垂直空间不自动参与有效性判断。

## 战斗数据需求

至少表达：

- 模板 ID、长期角色卡 ID、战斗实例 ID；
- 单位类型与相对关系 `ally | enemy | neutral | unknown`；
- 当前/最大 HP、临时 HP；
- 职业资源、次数型资源与法术位；
- 动作、附赠动作、反应和剩余移动力；
- 先攻值、先攻组、当前行动者、轮数和回合序号；
- 方格坐标、占位尺寸和高度；
- 状态、专注、持续时间与到期时点；
- 范围定义、几何变换、覆盖格、自动候选与 DM 最终目标；
- 操作前后差异、事件时间、事件来源与规则依据。

## 临时验证库

候选验证库只含未来可迁移数据结构，不得硬编码到页面组件：

### 怪物模板

1. 地精武者（Goblin Warrior）：小型、近战/远程、附赠动作；固定遭遇生成两个实例。
2. 火巨人（Fire Giant）：巨型 3×3、多格占位、远程投掷、推离与短时劣势。
3. 眼魔（Beholder）：大型 2×2、飞行高度、次数资源、反魔法锥域与多种持续状态。

### NPC 模板

1. 斥候（Scout）：远程、多重攻击；关系设为 `ally`。
2. 祭司（Priest）：治疗、祝福、灵体卫士与次数资源；关系设为 `ally`。
3. 魔法师（Mage）：火球、寒冰锥、飞行、迷踪步、反应法术与次数资源；关系设为 `neutral`。

### 玩家角色候选

1. 15 级散打武者（Warrior of the Open Hand Monk）：高速近战、两次攻击、疾风连击、附赠动作竞争、反应、15 点功力、临时 HP 与状态。
2. 15 级塑能师（Evoker Wizard）：19 个准备法术、1～8 环法术位；固定验证法术至少含油腻术、火球术、飞行术、加速术、闪电束、妖精召唤术与寒冰锥。

完整属性、专长、装备和准备法术表必须在 Implementation 前或期间按 Rules Baseline 生成并由规则人工核对；本 Draft 不凭常识补齐。

## 存档、撤销与修正

`v0.1.0` 必须支持自动保存、新建、手动保存、读取、刷新恢复、完整 JSON 导出/导入、重置验证数据、撤销上一步有效操作，以及对 HP、资源、先攻、状态和坐标的人工修正。

撤销与人工修正必须追加可读事件，至少记录对象、原值、新值、原因/类型、是否撤销/修正、轮次与行动者。

## 掷骰自动化边界候选

- 支持 `NdM±K`、d20 优势/劣势、公骰/暗骰与常用公式。
- 自动先攻可以读取单位修正值；固定测试使用可重放的预设骰序列。
- 每次随机结果必须写入事件；恢复与重放不得重新掷骰。
- 能力模板可以建议骰式、豁免与效果，但不会自动判断能力是否合法。
- 批量伤害/治疗只在 DM 确认后应用；抗性、免疫、掩护、视线和复杂豁免结果默认由 DM 输入或逐目标修正。
- 不实现公平性服务器骰子。

## 明确排除

`v0.1.0` 不包括全量单位库、全职业自动结算、完整规则搜索/规则引擎、六角格实现、3D、美术地图、复杂地图编辑、墙体/碰撞/视线/掩护、多用户实时同步、账户/权限/房间、NAS 部署、公平性服务器骰子、复杂动画或完整召唤物控制。
