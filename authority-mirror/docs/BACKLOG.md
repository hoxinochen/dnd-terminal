## 1. 本地试行管理规则

本节是 DND Terminal 对 Backlog v2 的本地试行规则，尚不是 ESG Released Profile。规则经过数次真实的记录、整理、排序和选版验证后，才可作为候选实践提交 Engineering Schema Governance；在 ESG 正式发布且本项目明确采纳前，不得宣称为通用规范。

### 1.1 单个 Backlog 必须回答的问题

每个正式 BL 最低应让人快速知道：

1. 这是做什么；
2. 为什么需要；
3. 准备沿什么方向处理；
4. 当前完成到什么程度；
5. 优先级由谁决定；
6. 它从哪里产生、与哪些 BL 有来源或拆分关系；
7. 范围、非目标、依赖和阻塞是什么；
8. 下一次打开它时应先决定什么。

Backlog 只保存足以理解和继续规划的信息。完整数据模型、详细交互、测试计划、验收标准、版本号和实施记录应在条目进入具体交付后由 ABC、DESIGN、TESTING、IMPLEMENTATION、REVIEW 或 Release/Archive 记录承担。

### 1.2 完成情况

总览和具体条目必须分别提供中文自然语言与稳定英文枚举。中文负责用户理解，英文负责跨文档一致性。

| 完成情况（中文） | Status (English) | 含义 |
| --- | --- | --- |
| 已收录，待进一步澄清 | Captured | 已记录，但目标或边界仍需整理。 |
| 正在整理方向 | Shaping | 正在讨论拆分、范围或依赖。 |
| 方向已确认 | Direction Confirmed | 已确认值得做及基本方向，尚未进入获批交付。 |
| 可进入版本设计 | Ready for ABC | 前置问题已基本清楚，可以候选编写 ABC。 |
| 交付进行中 | In Delivery | 已有获批交付，正在实施或评审。 |
| 部分已交付，仍有剩余工作 | Partially Delivered | 已有正式交付证据，但本条仍有未完成范围。 |
| 已交付 | Delivered | 本条职责已有正式交付证据，剩余需求由其他 BL 承担。 |
| 暂时受阻 | Blocked | 存在明确外部或前置阻塞。 |
| 已关闭 | Closed | 已取消、合并、取代或确认无需继续。 |

暂缓处理不是完成情况。一个条目可以同时处于“方向已确认”和“当前暂缓”，但不得把 Deferred、优先级与完成状态混写在同一字段。

### 1.3 优先级

| 优先级 | 含义 |
| --- | --- |
| P0 最高/紧急 | 已确认的数据损坏、安全或项目阻断；不得为了强调重要性而滥用。 |
| P1 高 | 近期应优先处理，或属于长期不可放弃的核心方向。 |
| P2 常规 | 有明确价值，前置满足后按正常节奏安排。 |
| P3 中低 | 确定保留，但目前不应占用近期容量。 |
| P4 低 | 远期、投入巨大、产品边界较弱或依赖尚不成熟。 |
| 条件门禁 | 不参与产品排序，但触发对应生命周期时必须执行。 |
| 不适用 | 已交付且本条没有剩余工作。 |

User 明确表达的优先级高于 AI 判断。User 未表达时，AI 必须给出明确建议并标注 AI-assessed；User 确认后，记录为 User，同时在来源追踪中保留“AI 提议、User 确认”的事实。

本文件当前全部优先级由 User 于 2026-09-04 确认采用 AI 的首次整体排序，因而 Priority Authority 统一为 User。未来调整以最新明确 User 决定为准。

### 1.4 来源追踪

只记录真实存在的关系，不为不存在的字段填“无”。

- **Origin：** 最初问题、需求或观察来自哪里；
- **Proposed By：** 谁把它整理为正式 BL；
- **Derived From：** 由哪些既有需求共同推导；
- **Split From：** 从哪个过大目标拆出；
- **Parent / Child：** 目标与子交付关系；
- **Related：** 有关联但不存在包含关系；
- **Decision Record：** User 确认、否决、改变优先级或边界的重要决定。

用户提出抽象目标、AI 提议拆分、User 确认时，Origin 仍是 User；AI 只记录为拆分建议者，不得把需求来源改写成 AI。

### 1.5 AI 推进建议边界

AI 可以结合当前架构、技术债、依赖和 User 优先级，给出跨 BL 推进建议。目标是用最小且可控的基础交付解锁更多高价值需求，而不是为了连接数量制造巨型版本。

该建议：

- 是非权威、可重新生成的规划参考；
- 可以表达依赖链、解锁关系、并行支线和暂缓原因；
- 不得替代 Roadmap 的跨交付正式方向；
- 不得替代 ABC 的版本范围、验收、回滚和批准；
- User 确认的跨版本方向应进入 Roadmap；选中的下一交付应另行进入 ABC。

### 1.6 临时记录与收口

版本进行中产生、尚未完成整理的想法先进入 Backlog Inbox，不立即分配正式 BL 编号，也不改变当前 ABC。

版本结束整理活文档时，每条临时记录必须被提升、归并、拆分、转移或删除。提升后的正式 BL 应保留临时编号作为 Origin；被删除的普通噪声无需永久占据 Backlog，重要 User 决定才保留简短原因。
