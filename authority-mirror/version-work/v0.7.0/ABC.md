## 0. 交付定位与当前门禁

`v0.7.0` 是一次以真实 DM 跑团工作流为中心的 UI 架构、信息架构和视觉系统交付。它把现有战斗、地图、角色、单位库、日志、掷骰与设置能力组织为稳定工作区；以只读 Status/Workspace Projection 统一信息表达；为战斗、地图和角色提供受控布局配置；并在不改变现有 D&D 规则、Domain Authority 与 DM 最终裁定边界的前提下，提高信息密度、可扫描性、触屏与窄屏可用性。

本交付不是单纯“换皮”，也不是借重构扩展玩法。它必须同时解决：全量页面重渲染、渲染后 DOM 注入、分散状态拼接、信息层级不清、卡片嵌套、工作区拥挤、视觉不一致、UI 偏好与团务事实边界不清，以及未来状态扩展可能再次破坏界面一致性的问题。

本 ABC 已由 User 于 `2026-09-01` 正式批准并冻结，是 v0.7.0 唯一实施范围合同。冻结本文只确立范围、架构、UX/UI、兼容、测试和回退边界，不自动授权 Implementation、Testing 执行、产品代码、分支、Commit、Push、Review、Release、Archive、部署、公开发布或再分发。任何超出冻结边界的变更必须通过 Amendment 重新获得 User 批准。

## 2. B——Domain Authority 与 Status Projection Contract

### B-1 Authority 不合并

v0.7.0 不建立一张“大而全”的独立信息表，也不把多个 Authority 对象合并为一个可互相覆盖的数据对象。以下职责继续保持分离：

- `CombatSession`：当前战斗事实；
- `CharacterSheet`：长期角色事实与修订；
- `UnitTemplate`：长期单位模板；
- `CombatantInstance`：单场单位事实；
- `TurnState`：轮次、顺序与当前行动者；
- `EffectInstance`：效果实例、来源与到期；
- `CombatEvent`：顺序历史与补偿事件；
- `UiPreferences`：纯界面偏好，不是团务事实。

战斗会话 Snapshot 与顺序 Event Log 继续是战斗运行 Authority。长期角色卡、模板、战斗实例、地图投影和事件历史不得因 UI 重构而变为一份共享可写对象。

### B-2 Projection 是只读中间层

数据流固定为：

```text
Domain State + Event Log
→ Entity Projection / Workspace Projection
→ 战斗 / 地图 / 角色 / 单位库 / 日志 / 掷骰 / 设置
```

Projection 可以读取多个 Domain 对象并形成适合页面消费的 View Model，但必须满足：

- 不拥有业务事实；
- 不直接持久化为第二份 Authority；
- 不接受页面直接写入；
- 可以随时从 Domain 重新计算；
- 缓存丢失不得造成团务数据丢失；
- 不自动补齐 D&D 规则、合法性、时间或未知字段；
- 不把 UI 推导结果反写到 CharacterSheet、CombatantInstance 或 Event Log。

用户操作必须经统一 Command 层校验并修改 Domain，再追加适用事件、保存会话、重新计算 Projection，最后更新工作区。页面不得直接通过 DOM 或 Projection 修改业务状态。

### B-3 状态 Facet

状态投影至少按以下 Facet 组织，不压缩成一个笼统 `status`：

| Facet | 最低职责 |
|---|---|
| Encounter | 准备、进行、结束、清理及恢复阻塞状态 |
| Participation | 是否仍为本场参与者 |
| Presence | 在场、临时离场、待投入或其他已记录位置状态 |
| Life | 正常、濒死、稳定、死亡、转化、待复核及兼容值 |
| Turn | 当前、已行动、未行动、跳过或无资格 |
| Action | 普通行动、仅死亡豁免、完全阻断或待确认 |
| Effects | 效果实例、旧兼容状态、来源、专注和到期 |
| Control | 主人、控制者、关联与受控关系 |
| Pending | 待摆放、待裁定、待同值排序、待回写或待确认事项 |
| Confidence | 已确认、DM 裁定、兼容推导、未知或待复核 |

紧凑摘要只展示身份、HP、最高优先级生命/回合状态和最紧迫待办；完整 Inspector 展示全部适用 Facet、来源、开始/到期、DM 修正、兼容说明及 Event ID。

### B-4 优先级与未知值

紧凑状态优先级固定为：

```text
阻塞错误
→ 必须立即处理的 DM 决定
→ 当前回合强制动作
→ 生命危险
→ 在场/参与异常
→ 控制关系异常
→ 即将到期的效果
→ 普通 Buff/Debuff
→ 参考与审计信息
```

未知、不完整和未来状态不得静默隐藏或默认显示为正常。Projection 至少保留原始值、`unknown / needs-review` 身份和人类可读原因；旧组件或未识别状态必须安全降级为“未识别状态”，不得覆盖原始数据。

未来版本新增状态时必须同时声明：所属 Facet、Authority、写入 Command、旧数据默认、Projection 映射、摘要优先级、Inspector 表达、工作区可见性和组合状态测试。禁止页面局部硬编码新的状态中文、颜色和行为。

## 3. C——工作台与工作区架构

### C-1 稳定应用外壳

应用外壳负责：

- 产品与会话身份；
- 当前战斗阶段、轮次与当前行动者摘要；
- 七个主要工作区导航；
- 保存失败、迁移失败、恢复阻断等全局提示；
- 当前工作区出口；
- 布局设置入口；
- 运行时可证明的 Delivery、Session Schema、本地私有与迁移来源信息。

切换工作区不得销毁并重建整个应用外壳。业务操作不得以“重建整个 `#app` 并重新绑定全部事件”作为唯一更新机制；页面更新应收敛到工作区、面板或明确上下文边界，并防止重复事件绑定。

运行时 UI 不声称 Git Commit/Push、Release、Archive、Deployment 或 Public Release 状态，因为这些事实由文档 Authority 和交付记录管理，不由浏览器运行态证明。

### C-2 七个工作区

保留现有信息架构与中文名称：

1. 战斗；
2. 地图；
3. 角色；
4. 单位库；
5. 日志；
6. 掷骰；
7. 设置。

每个工作区拥有明确渲染和交互边界，但所有战斗相关页面继续通过同一 Command API 操作同一个权威 CombatSession，不建立页面级可保存副本。

工作区导航采用可表达页面身份的本地路由；建议使用 hash 路由。刷新、前进、后退和无效路由行为必须可预测。切换工作区不得静默提交、取消或改写高风险草稿；会话型草稿的刷新恢复语义必须逐项保留或明确迁移。

### C-3 Panel Registry

面板使用统一注册合同，至少声明：

- 稳定 Panel ID；
- 所属工作区；
- 标题与简短职责；
- 是否核心面板；
- 默认顺序；
- 默认宽度；
- 是否允许隐藏；
- Projection 输入；
- 交互/Command 责任；
- 空状态、错误状态和未知状态表达。

Panel Registry 是项目内部 UI 组合边界，不是插件系统，不允许加载任意代码、第三方扩展或远端组件。

## 4. D——信息架构与高密度呈现

### D-1 一屏五问

战斗工作区不切页应能回答：

1. 现在是第几轮、谁正在行动；
2. 当前单位还能做什么；
3. 场上有哪些重要异常；
4. 刚刚发生了什么；
5. 现在有哪些事项需要 DM 决定。

完整规则来源、Schema、Revision、Event Payload 和低频审计信息不得与上述运行信息争夺首屏优先级，但必须可追溯。

### D-2 三层信息

- **持续态势层：** 会话、阶段、轮次、当前行动者、核心生命/行动状态、保存或恢复阻塞；
- **当前任务层：** 当前行动、目标、资源、效果、位置、死亡后处理、投入、回写与 DM 决定；
- **参考审计层：** 规则来源、Snapshot、Revision、Schema、迁移、Event ID、完整 Payload 和 DM 修正依据。

页面按 DM 任务链组织，不按数据库字段平均铺开。正常行动、死亡处理、地图摆放和战后结算必须提升各自相关信息，降低无关操作权重。

### D-3 工作区密度

- **战斗：** 持续态势、行动轮、当前行动工作区、上下文 Inspector 和最近结果反馈形成稳定层级；
- **地图：** 地图为主体，只直接承载空间决策所需信息；HP、效果、来源和规则详情进入 Inspector；
- **角色：** 首屏突出身份、Revision、可投入性、核心战斗数据、缺失/冲突、长期效果和关联单位；完整字段按区域展开；
- **单位库：** 来源、类型、归档、准备/投入与编辑操作有明确列和优先级；
- **日志：** 事件按轮次/阶段组织，技术 Payload 默认折叠，补偿与 DM 修正具有非纯颜色标识；
- **掷骰：** 骰式、公开/暗骰、优势/劣势、最终结果和最近历史优先；不增加 3D 骰子；
- **设置：** 会话/地图、显示/布局、保存/导入导出、恢复/危险操作、版本/本地数据分组。

### D-4 标准与紧凑两档

- `standard` 为默认，保留较完整辅助说明和较宽操作目标；
- `compact` 缩小面板间距、表格行高和次级说明占用，在笔记本与高密度战斗中显示更多内容；
- 两档不得改变功能、Authority、事件、状态维护或核心控制可达性；
- 紧凑模式不得把关键触控目标缩小到难以操作，也不得隐藏阻塞事项；
- 不提供任意字号、任意 Padding 或第三个高度自定义密度模式。

### D-5 防止卡片汤

视觉层级最多为页面背景、一级工作区面板和必要的单层强调区域。简单信息优先使用行、表格、Definition List、状态条、分组标题和分隔线；只有需要独立识别、选中或操作的对象才使用卡片。不得继续以多层嵌套卡片和同等视觉权重表达全部信息。

## 5. E——可配置布局与 UI Preferences

### E-1 可配置范围

只有战斗、地图和角色三个复杂工作区在本版本提供布局配置。单位库、日志、掷骰和设置接入统一工作区架构，但保持固定布局。

允许的配置只有：

- 辅助面板显示/隐藏；
- 通过“上移/下移”调整顺序；
- `narrow / standard / full` 三档面板宽度；
- `standard / compact` 两档信息密度；
- 恢复当前工作区默认；
- 恢复全部工作区默认。

不使用自由拖拽排序、任意像素缩放、浮动窗口、自由画布、多套命名布局或云端同步。

### E-2 核心面板保护

以下最低核心区域不得隐藏：

- 战斗的行动轮、当前行动者核心状态与当前强制流程；
- 地图主体；
- 角色选择和当前角色主体；
- 保存失败、迁移失败、恢复阻断和数据安全提示。

隐藏辅助面板只改变呈现，不删除数据、不停止事件、状态、专注、效果到期、回写候选或日志维护。

### E-3 独立 UI Preferences

UI 偏好独立于 CombatSession，至少使用独立版本化存储键：

```text
dnd-terminal.v0.7.0.ui-preferences
```

偏好至少包含最近工作区、面板显隐、顺序、宽度和密度。它们不得进入 CombatEvent、CharacterSheet、战斗 JSON 导出或业务更新时间。偏好损坏时回退默认布局并给出非阻塞提示，不得阻断 CombatSession 恢复。

当前工作区、角色详情内部页签、显示已归档角色和布局编辑状态应从团务事实中分离。范围预览、待入场、死亡处理等与恢复安全有关的会话型草稿不得为追求架构纯度而一次性移除；Implementation 必须逐项证明其保留或迁移语义。

## 6. F——统一视觉系统与可访问性

### F-1 视觉定位

视觉方向固定为“专业指挥台 + 克制的奇幻气质”：

- 深海军蓝/石墨色为背景层；
- 暖金色用于品牌、当前行动者和关键选择；
- 蓝色用于普通交互；
- 红、橙、绿只用于危险、警告、成功等语义；
- 状态同时使用文字、形状、边框或图标，不以颜色作为唯一表达；
- 减少装饰性渐变、重复描边、过度阴影和嵌套卡片；
- 不复制第三方品牌，不引入 Carbon、React、Vue 或远端 Web Components。

成熟工作台、设计系统和 VTT 只作为结构、密度、地图主体与视觉完成度参考；最终 CSS、组件和品牌表达必须为本项目本地实现。

### F-2 Design Tokens 与组件

建立统一的颜色、文字、背景层、边框、交互、语义状态、间距、圆角、阴影、字体、字号、动画与 z-index Token。新增页面和组件不得各自任意选择颜色和间距。

本版本统一实际使用的：按钮、输入、选择器、复选框、分段选择、面板、统计项、状态条、详情行、Tab、导航、通知、错误、表格、Badge、空状态、Inspector、布局设置和二次确认。不开设独立组件库产品、Storybook 或设计系统站点。

中文正文使用本地系统字体；技术 ID、Schema、骰式和 Event ID 使用等宽字体。不得依赖外部字体或素材 CDN。

### F-3 可访问性与响应式

最低目标为 WCAG 2.2 AA 相关可验证要求：

- 普通文字对比度至少 `4.5:1`，大字至少 `3:1`；
- 键盘焦点清晰可见且不被固定区域遮挡；
- 状态和操作意义不只使用颜色；
- 文字放大至 200% 不丢失核心内容或功能；
- 指针目标满足最低尺寸/间距，主要按钮以约 40px 或更高的可操作高度为目标；
- 桌面、普通笔记本和窄屏都能完成主要流程；
- 动画只用于必要切换和反馈，建议约 120–180ms，并尊重 `prefers-reduced-motion`；
- 不加入背景动画、闪烁、粒子、复杂特效或 3D 骰子。

## 7. G——兼容、迁移与回退

### G-1 冻结回退锚点

回退锚点固定为 v0.6.0 的冻结 ZIP、manifest、Authority、37 文件代码快照、测试记录、归档摘要及 Workspace 技术基线 `3464d17`。v0.7.0 不修改 v0.6.0 的 ABC、Amendment、Implementation、Testing、Review、Release Notes、Archive、发布包、快照、manifest、校验记录或旧存储值。

### G-2 Domain Schema 默认不变

Status/Workspace Projection 是只读呈现层，默认不要求新的 Domain Schema。v0.7.0 应优先继续读取 v0.6.0 已有的 Session Schema 和对象关系。

如果实施证据表明必须新增业务字段、改变 Event 语义或执行破坏性 Schema 迁移，Implementation 必须停止并请求 ABC Amendment 与 User 重新批准；不得把缺失业务事实藏在 Projection 或 UiPreferences 中。

允许的字段变化只应是兼容扩展：旧数据可读、缺失值明确为 `unknown / not-applicable`、旧事件不改写。删除、重命名或改变既有字段/事件含义不在本 ABC 授权候选范围内。

### G-3 copy-on-write

v0.7.0 使用独立后继会话键，建议固定为：

```text
dnd-terminal.v0.7.0.workbench.session.current
```
