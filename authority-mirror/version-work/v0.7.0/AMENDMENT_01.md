本 Amendment 候选来自 v0.7.0 实施后的 User 视觉与交互复核。目标是完成四项仍影响真实使用的收口：修复地图网格与背景容器的结构性越界；让掷骰工作区承担可浏览历史和复合骰式；把角色创建收敛为单一、互斥且可调整宽度的任务流；把历史验证入口移出正常跑团界面并集中到设置。

## 1. 地图视口与网格画布修正

### 1.1 批准候选

1. 地图必须拆分为稳定的 `MapViewport` 与按实际格数定尺寸的 `MapCanvas`：前者负责可见框、深色底纹、圆角与双向滚动；后者负责网格、棋子与范围层。
2. 网格、边框和底纹必须由同一个实际尺寸画布承载，不得继续出现网格线横向超出深色背景、背景只覆盖容器宽度或纵横行为不一致。
3. “适应屏幕”允许缩放整个画布以总览；“战术操作”保持固定格子尺寸并允许滚动或平移。两种模式不得改变地图坐标、棋子位置、范围结果或事件。
4. 地图标题区应持续显示格数与每格距离，并提供回到地图主体/当前单位的可达控制。滚动条和溢出方向必须可感知，不能以裁切隐藏内容。
5. 本项只修复现有空白方格地图的容器、尺寸和查看行为；不引入地图图片、动态边界、负坐标、地图资源存储或新的地图事件。

### 1.2 验收

- 桌面宽屏、普通笔记本与窄屏下，网格背景、边框和底纹完整一致；画布可以大于视口但不越出视口绘制。
- 横向和纵向超出都在地图视口内部滚动；工作区、后续面板和页面背景不被网格撑破。
- 适应屏幕与战术操作切换后，棋子、范围候选和坐标事实不变。

## 2. 掷骰历史

### 2.1 批准候选

1. 掷骰工作区增加固定高度、纵向滚动的历史区域；最新结果置顶，最低展示最近 `100` 次骰点事件。
2. 视图上限只限制掷骰页面的投影，不得删除、截断或改写 Event Log 中更早的骰点事实。
3. 历史条目至少显示原始骰式、规范骰式、各骰组结果、常数修正、总值、优势/劣势、公开/暗骰标记和时间/回合上下文。
4. 提供清晰的历史计数与“回到最新”；滚轮、触控板、触屏和键盘都应可浏览，滚动位置属于临时 UI 状态。
5. 骰点事件不得为不可撤销的纯随机记录复制完整战斗撤销快照。可新增统一的非可逆事件记录路径或等价参数，但不能削弱其他可撤销 Command 的补偿语义。

### 2.2 验收

- 连续生成超过 `100` 次骰点后，页面稳定展示最近 `100` 次且能滚动到最旧可见项；Event Log 仍保留全部事件。
- 刷新和导入不会重新掷骰；历史结果来自已保存事件，不从骰式重新求值。
- 长序列骰点不会因重复保存整份撤销快照造成与次数成比例的会话快照膨胀。

## 3. 复合骰式与快捷输入

### 3.1 正式骰式

1. 骰式从单一 `NdM±K` 扩展为有符号项序列，最低支持：`2d6+2d4+1`、`1d20+5`、`2d8-1d4+3` 与空格/大写 `D` 的规范化输入。
2. 每个骰项独立保存符号、数量、骰面、逐骰结果和小计；整数项单独保存。事件同时保存 `formulaRaw`、`formulaCanonical`、结构化 `terms` 与最终总值，历史回放不得重新解析或重掷。
3. 最低安全限制固定为：最多 `20` 项、单组最多 `100` 颗骰、单次最多 `200` 颗骰、骰面 `2–1000`、整数修正绝对值不超过 `100000`。
4. 优势/劣势只允许用于一个正向 `1d20` 加零个或多个整数修正的表达式；复合骰组启用优势/劣势时必须拒绝并解释原因。
5. 本次不实现括号、乘除、函数、爆骰、保留/丢弃最高最低、重掷、规则合法性或自动效果结算。

### 3.2 数字快捷输入

1. 数字串快捷输入以标准骰面 `d4 / d6 / d8 / d10 / d12 / d20 / d100` 为候选，单个快捷骰组的数量限 `1–9`；尾部可解析为固定修正。
2. `110284` 必须可预览为 `1d10+2d8+4`。快捷输入先产生规范化预览，User/DM 确认后才掷骰，不得在输入阶段写事件。
3. 当数字串存在多个合法拆分时不得静默猜测；必须列出候选规范骰式，由 User/DM 明确选择。无法唯一、安全解析时保留原始输入并引导使用正式骰式。
4. 快捷输入与正式骰式共用同一个解析、限制、结构化结果和事件合同，不得建立两套互不兼容的骰点语义。

### 3.3 验收

- 覆盖多骰组、正负骰项、正负常数、空格、大写、边界值、超限、非法连续运算符和歧义数字串。
- `110284` 的预览、确认、逐骰结果和历史显示一致；歧义输入在选择前零写入。
- 旧 `NdM±K` 继续兼容，旧骰点事件继续可读且不被改写。

## 4. 角色创建任务流

### 4.1 单一入口

1. 角色工作区只保留一个主要入口“创建角色”。进入后显示“受控 Excel 导入”和“手工创建”两个子选项。
2. 两种创建方式互斥展开，同一时刻只显示一个创建面板；提供“返回方式选择”和“关闭”。不得再让两个完整表单长期占据角色首屏。
3. 创建成功后关闭创建流程并选中新角色；取消或切换工作区不得产生空白 CharacterSheet、CombatProjection 或 CombatEvent。

### 4.2 Panel Registry 与草稿保护

1. 当前活动的创建面板接入角色工作区 Panel Registry，并允许 `narrow / standard / full` 三档宽度；Excel 导入和手工创建分别记忆自己的宽度。
2. 创建方式、宽度和面板呈现属于 `UiPreferences` 或受控临时 UI 状态，不得进入 CharacterSheet、CombatSession、CombatEvent 或战斗 JSON。
3. Excel 已解析但未确认时显示“未确认草稿”；关闭或切换方式必须允许明确保留/恢复或放弃。手工表单也不得因调整尺寸、重排或工作区重渲染而丢失已填写内容。
4. 未确认草稿不得成为长期角色 Authority；只有最终确认才创建或修订 CharacterRecord。

### 4.3 验收

- 正常角色页不再同时出现导入与手工创建大面板。
- 两种创建方式切换、调整宽度、切换工作区和窄屏使用均不发生遮挡或意外提交。
- 草稿保留/放弃语义明确，长期角色、战斗实例和导出数据保持隔离。

## 5. 设置中的开发验证工具

### 5.1 入口与内容

1. 在设置工作区建立默认折叠的“开发与验证 → 开发验证工具”，显示“仅供开发验收，不属于正常跑团流程”的持续警告。
2. 正常角色页移除 `M1-S4 本地验证角色` 与 `旧版本地验证预设` 的入口，但不自动删除已经创建的角色记录、旧会话或兼容数据。
3. 开发验证工具包含：
   - M1-S4 三个结构夹具：塑能师、法师/牧师、莉亚混合来源；
   - 两个旧版角色兼容预设：15级散打武者、15级塑能师；
   - 原已隐藏的旧版固定战斗数据入口。
4. 旧版角色预设必须按遭遇阶段显示“兼容加入”或“兼容待入场”；当前阶段不可使用时禁用并说明原因。
5. 旧版战斗按钮改名为“载入 v0.1 固定战斗验证场景”，不得继续使用含糊的“重置验证数据”。

### 5.2 数据安全

1. 载入固定验证场景属于会替换当前 CombatSession 的危险操作，必须二次确认并清楚列出影响；存在待审核 PostCombatDiff 时必须阻止。
2. 确认界面至少提供“先导出当前会话并载入”和“取消”；长期角色库不得随验证战斗场景被清空。
3. 开发验证工具不进入普通工作区 Panel Registry，不获得正常产品功能或规则正确性身份；它只复用现有受控夹具和兼容路径。
4. 隐藏入口不得删除旧 Session 的兼容读取能力，也不得把验证夹具混入默认单位库、角色列表或战斗数据。

### 5.3 验收

- 正常角色页和战斗控制区不显示任何验证夹具或固定场景按钮。
- 设置页可以创建三类 M1-S4 夹具、按阶段投入两个旧角色预设，并经安全确认载入固定战斗场景。
- 取消、阶段不允许、存在待审核差异和导出失败均不会覆盖当前会话。
