## 1. 本次实施内容

### 1.1 数据与迁移

- 新增产品 Workspace 的 `src/encounter.js`，定义 `v0.2.0` 的五个本地私有 `reference` 模板，以及 `EncounterMember`、`CombatantInstance` 的构造和 `v0.1.0 → v0.2.0` 会话迁移。
- 模板加入遭遇时复制 `templateSnapshot`；确认遭遇时再次复制成员成为战斗实例。HP、资源、状态、位置、朝向和发射口不共用引用。
- 新会话带有 `encounter.phase: preparation`，并使用独立的 v0.2 当前会话存储键，不自动接管浏览器中的 v0.1 localStorage。旧 `v0.1.0` 文件仍可通过显式导入迁移为 `confirmed`，不倒推或伪造第 0 回合。
- 模板库采用独立 localStorage 键；战斗会话继续作为单一 `CombatSession` 保存和导出。
- 经 D2-008-A1 单独准入，参考模板由五个扩展至七个：新增火巨人和眼魔。扩展 DLC 的火巨人 AC 更新为 `18`；眼魔保留经字段核验的飞行、传奇抗性和传奇动作池。原五样本冻结包未改动。
- 七个准入参考模板统一在模板快照中携带紧凑的 `referenceActions` 详情。原五样本使用冻结 Ledger 中的攻击加值、触及/射程、伤害与必要命中效果；火巨人和眼魔使用 D2-008-A1 证据。旧会话只在 `sourceEntryId` 精确一致时补充展示，不改变战斗实例。
- 既有 v0.1 本地私有角色与 NPC 继续作为 `legacy fixture` 预设，但 UI 身份重新分离：15 级散打武者和 15 级塑能师只在“角色”页加入遭遇；斥候、祭司和魔法师作为 NPC 保留在单位库。它们不是新增的规则资料准入，也不构成完整角色构筑或角色导入。
- 角色预设的资源与法术位会随 `EncounterMember → CombatantInstance` 快照复制；确认遭遇后创建独立的 `state.characters` 差异记录，战斗期间不反写长期基线。

### 1.2 单位模板库

- 新增 `reference`、`custom`、`variant` 的来源标识；变体记录 `baseTemplateId` 和创建时 `baseTemplateRevision`。
- 支持新建、编辑、复制为变体、归档与恢复。归档仅阻止未来加入遭遇，不删除历史快照。
- 支持名称、简称、颜色、阵营、体型、AC、HP、速度、先攻调整值、占位、动作、资源和备注。字段均由 DM 维护，不做 CR、平衡性或规则绝对合法性判断。
- 七个准入参考怪物保存条目显式先攻调整值：丧尸 `-2`、骷髅 `+3`、地精喽啰 `+2`、食人魔 `-1`、狼 `+2`、火巨人 `+3`、眼魔 `+12`；自定义与变体模板的值由 DM 编辑。

### 1.3 遭遇准备与第 0 回合

- 新会话从第 0 回合开始；DM 可从单位库多次加入同一模板，并逐成员修改显示名、初始 HP、关系、资源、状态、位置、朝向和发射口。
- 准备状态会自动保存，可恢复继续编辑；第 0 回合移动不消耗移动力，也不写战斗事件。
- 只有明确“确认遭遇”才会生成 `encounter.confirmed` 事件、物化 `CombatantInstance` 并开放既有投先攻路径。
- 确认后不能返回任意第 0 回合编辑；未确认草案只能通过二次确认的“放弃准备”清空，且不会影响已确认战斗。
- 正式开始先攻后提供“结束战斗”。确认后追加 `combat.ended` 事件，将遭遇置为 `ended`，并按后续选择导出记录、清空战场或进入只读战后清理。角色 HP 与资源不自动回写长期数据。

### 1.4 修订范围：参战生命周期与战斗收尾

- 经 `2026-08-12` 修订批准，`EncounterMember.deployment` 支持 `field` 与 `reserve`。场外预备保存成员快照、HP、资源和状态，但不占据第 0 回合地图，也不会在确认遭遇时物化为战斗实例或进入先攻。
- 新增显式 `CombatantInstance.presenceStatus`（`on-field` / `temporarily-away`）、`participationStatus`（`active` / `ended`）、`eligibleFromRound` 与 `cleanupRemoved`。临时离场不删除实例；再入场仍使用原实例 ID、HP、资源、法术位、先攻和事件历史。
- 已开始战斗可从单位库或角色栏创建未确认 `EntryDraft`，或将场外预备投入战场。快速加入只建立“先攻未配置”的待入场项目，不投骰、不增加正式参战者或事件；确认页由 DM 设置名称、关系、HP、资源、状态、位置、现场投骰/手填先攻与同值先后；确认后才追加投入事件并创建实例。
- 现场投骰采用 `1d20 + 可编辑先攻调整值`，保存 `initiativeRoll`、`initiativeModifier`、`initiative` 和模式；手填输入视为最终值，不重复叠加调整值。整批确认会列名拦截所有先攻未配置的新单位。战斗开始、首次投入、再入场重投均使用同一计算口径。
- 经 `2026-08-13` 交互修订：待入场主卡片默认显示“`d20 + 调整值 · 待投`”，不再把“先攻未配置”作为主要状态；DM 可逐项投骰或点击“为待投单位批量骰先攻”。精确地图 X/Y 坐标移至“详细配置”，主路径改为跳转地图拖拽摆放。确认时若仍有待投单位，系统明确询问是否立即批量投骰后继续，不会静默投骰或覆盖手填/已投结果。
- 首次加入与再次入场根据插入后的先攻位置，明确写入 `eligibleFromRound`：本轮位置尚未经过则本轮可行动，否则从下一轮起可行动；同值顺序由 DM 在确认页选择“之前 / 之后”。
- “暂时离场”“结束参战”“再次入场”均为追加事件。当前行动者离场会跳过场外单位并安全推进至下一个可行动实例；有效先攻条和地图只显示在场、仍参战单位。
- 用户于 `2026-08-12` 追加修订临时离场语义：离场时立即清除临时 HP、手工状态、目标身上的 Buff/Debuff，以及由该实例维持的专注效果；共享效果只移除该实例目标，不影响其他目标。当前 HP、已消耗资源、法术位、原先攻和实例 ID 保持不变。
- 再次入场不恢复离场时已经清除的效果，只重新选择位置与先攻处理。HP 为 `0` 的实例不能再次入场并获得正常行动资格；死亡与死亡豁免仍延期至 `BL-020`。
- 最后一个可行动单位离场后，战斗进入“等待增援”状态，不结束战斗或伪造新回合；DM 仍可投入预备/临时单位或正常结束战斗。此状态下“下一回合”不会空转。
- 追加修复：当前行动者因伤害 HP 降至 `0` 时，系统立刻跳过该实例并顺延至下一名可行动者；若其位于先攻末位则进入下一轮。范围伤害和单位卡伤害走同一防卡死路径，事件记录 `turnAdvancedAfterDefeat`。
- 再入场改为与战斗中新增单位共用“待投入批次”：DM 可逐个填写/投先攻后直接进入地图拖动摆放，或暂存多名离场实例并与新加入单位一同批量摆放、一次确认。确认前再入场实例仍保持临时离场，取消批次不会改写该实例。
- 结束战斗前汇总在场、临时离场、未投入预备及未确认加入草稿。确认后前两类统一结束参战、预备标记为 `unused-reserve`、草稿丢弃。随后独立询问保存 JSON（不保存需二级确认）与清空地图；保留地图时进入只读清理模式，可逐个撤下棋子或撤下全部敌对棋子。
- 移除战后“审核回写”功能入口；当前战斗不会自动或手动回写长期角色 HP、资源或效果。长期结算继续严格延期至 `BL-019`。

### 1.5 修订范围：怪物/NPC 有限死亡处理（D2-015）

- `CombatantInstance` 新增 `lifeStatus`（`alive / dead / transformed`）、`deathRecord` 与 `transformationOrigin`。死亡状态与 `temporarily-away` 分离；旧会话若缺少该字段，一律安全迁移为 `alive`，即使 HP 已是 `0` 也不倒推死亡历史。
- 仅怪物/NPC 在伤害或范围伤害后 HP 降至 `0` 时，系统追加 `combatant.died`，清除临时 HP、手工状态、目标 Buff/Debuff 与该实例维持的专注，退出有效先攻与再入场，且保留可点选的尸体棋子。当前行动者死亡会沿用既有安全顺延逻辑进入下一位可行动单位。
- 角色 HP 为 `0` 时不会被自动标为死亡，界面明示“死亡豁免待后续实现”；未实现即时死亡、昏迷、稳定、死亡豁免、治疗/复活法术、材料或任何自动规则裁定。
- “当前选中者状态”中，死亡怪物/NPC 可由 DM 打开“处理死亡”：**DM 特许复起**保留原实例、以 `1 HP` 复起且不恢复资源、法术位、临时 HP、状态或效果；说明同时提供鼠标悬浮和触屏长按提示。
- **特殊复苏 / 转化**只允许选择单位库的怪物/NPC 模板。原死亡实例改为 `transformed` 并保留转化目标 ID；新模板被物化为独立 `CombatantInstance`，可直接在尸体位置确认，或暂存到地图与其他待投入单位一起批量摆放、一次确认。显示名默认推荐为“新模板名化原单位名”（例如“丧尸化狼”），DM 可任意改写；两条路径都追加顺序事件，不覆盖旧实例或模板。
- DM 特许复起说明改为卡片内固定可见的辅助文本，不再依赖会被后续状态卡遮挡的悬浮浮层。

## 2. 数据边界实现

```text
独立 UnitTemplate localStorage
  → EncounterMember（会话内快照与第 0 回合覆写）
  → encounter.confirmed（追加事件）
  → CombatantInstance（既有 CombatSession.combatants）
```

- `UnitTemplate` 不接收战斗内变更。
- `EncounterMember` 是确认前唯一可编辑的准备层。
- `CombatantInstance` 是确认后既有战斗、事件日志、补偿撤销和自动保存的唯一可变对象。
- 未确认阶段不产生先攻、行动经济或战斗移动事件；确认本身是明确的事件边界。
