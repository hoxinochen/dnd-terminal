## 1. 批准决定

本 Amendment 以三个受限决定补充冻结 ABC：

1. 需要创建新 CombatantInstance 的死亡后路径，不再要求 DM 填写地图 `x/y` 坐标；必须转入地图的可视摆放模式，只有放在空格后才可提交创建。
2. 死亡后处理入口先让 DM 选择人类可读的结果类型，再展示相应面板；产品 UI 不显示 `S1`、`S2A`、`S2B`、`S2C` 等内部 Slice 代号。
3. S2B 的亡灵必须成为施法者的正式**受控生物**关联，而非只有文字说明的临时 `controllerLink`。它与既有普通关联单位同处于角色档案的“关联生物”页签，但保持独立的数据结构、状态机与审计历史。

本 Amendment 不把任何法术的资格、材料、法术位、尸体资格、目标数量、升环、施法时机或续控合法性变成自动裁定。规则档案尚未逐项获准前，相关输入继续由 DM 确认。

## 2. 地图摆放合同

### 2.1 交互

- “获得新身体继续冒险”“制造受控亡灵”与“以亡灵身份继续冒险”在完成各自必填 DM 输入后，主按钮为 **前往地图摆放**。
- 进入专属地图模式后，地图显示待摆放的新实例预览；DM 通过点击地图格完成摆放，而非填写坐标。
- 已有任何棋子的格均不可作为落点，包括活动棋子、尸体棋子、暂离棋子或其他地图表现。不可落点必须有可读的占用反馈；确认动作必须禁用或拒绝。
- DM 取消地图模式时，返回原死亡后处理面板；不得创建事件、实例、棋子、先攻位置、战后候选或 CharacterSheet 修订。
- DM 在空格确认后，系统以单一原子操作写入新实例、地图落点、尸体处理、先攻决定及对应死亡后事件；提交前必须再次检查落点仍为空，避免陈旧 UI 状态绕过防呆。

### 2.2 边界

- “先移除尸体再在同格生成”不属于本 Amendment 的快捷例外。若尸体仍在目标格，该格即被占用；DM 应先使用已明确的尸体处理结果，或选择另一空格。
- 多格模板须检查完整占位 footprint 的每一格均为空；超出地图范围同样拒绝。
- S1 复用原实例与原棋子，不创建新身体，故不进入该地图摆放模式。

## 3. 四选一的死亡后处理入口

入口标题为 **死亡后处理方式**，默认不选中任何项。可选项和语义固定为：

| UI 名称 | 内部路径 | 人类可读结果 |
| --- | --- | --- |
| 恢复原身体 | S1 | 原 PC CombatantInstance 恢复并继续。 |
| 获得新身体继续冒险 | S2A | 原死亡实例保留；创建新的 PC 实例与独立角色卡。 |
| 制造受控亡灵 | S2B | 原死亡事实不撤销；创建受施法者控制的 monster/NPC 亡灵。 |
| 以亡灵身份继续冒险 | S2C | 创建独立的新 PC 角色卡与新 PC 实例。 |

- 内部事件名、测试名和 Authority 中的 Slice ID 可以继续使用技术标识；它们不得作为主要 UI 文案。
- 切换选项时，未提交的另一选项表单数据不得写入会话；如 UI 保留草稿，草稿只能是未提交的本地界面状态，不能成为事件事实。
- 每个二级面板必须在提交前再次显示其角色连续性、原角色卡、尸体、地图、先攻与战后写回结果，避免把 S2B 误读为 PC 复活。

## 4. S2B 受控生物的正式关联

### 4.1 页面结构与数据隔离

角色档案既有 **关联生物**页签保留，并在其中并列两个模块：

```text
关联生物
├─ 普通关联单位
└─ 受控生物
```

- `普通关联单位`继续使用既有一般关联语义；不得因本 Amendment 获得施法控制、命令距离、到期或失控效果。
- `受控生物`只显示与当前 CharacterSheet 正式关联的、仍受控或可追溯的控制生物。每项至少显示名称、Template、控制状态、命令距离、期限、剩余计数、创建事件、续控/失控历史与当前战斗投影（如有）。
- `controlledEntities` 是与既有 `linkedEntities` 并列的结构化关系集合；不得把两类关系混写到同一无类型数组、`note` 或来源 PC 的角色卡中。
- 每一受控生物必须有稳定的 `controlledEntityId`。关系项只保存受控实体引用、控制者 CharacterSheet 引用、Template/快照定位、控制档案、状态及审计事件引用；战斗中的 CombatantInstance 仍是独立实例，不与 CharacterSheet 相互覆盖。
- 施法者若没有可匹配的 CharacterSheet/CombatProjection，S2B 仍可保留本场 `controllerLink`，但不得伪造长期角色卡关联或战后写回候选。
- 原死亡 PC 的 `originCharacterRef` 仅可作审计来源；它不是受控生物的所有者、控制者或角色连续性关系。

### 4.2 控制状态与命令效果

最小控制状态为：

| 状态 | 可执行效果 |
| --- | --- |
| `controlled` | 控制者可在满足距离条件时创建命令事件。 |
| `out-of-command-range` | 控制未到期，但当前命令入口禁用；返回命令距离后恢复可命令资格。 |
| `expired-uncontrolled` | 控制到期；命令入口关闭，关联移入失控历史，生物/棋子/先攻历史保留。后续阵营、行动或移除由 DM 明确处理。 |
| `released` / `control-lost` | DM 解除或其他已记录原因导致控制结束；同样不可再由原控制者命令。 |
| `permanent-controlled` | DM 裁定的长期控制；不自动到期，仍可由明确事件解除或失去控制。 |

- 有效命令必须记录 `controlled-command.issued`（或等效的顺序 CombatEvent），包括控制者、目标受控实体、下次行动指令、当时距离、命令距离、轮次及 DM 原因。
- 命令距离是实际 guard：距离未知、目标不在场、控制状态不允许或超出距离时，命令提交必须拒绝，不得只展示文字提醒。
- 本 Amendment 不把“命令内容是否符合所有法术、动作、移动、伤害或目标规则”自动化为完整规则引擎。对于已准入的具体法术档案，可后续附加“无命令时回避”等规则化行为；在此之前，未下达命令后的行动继续由 DM 处理。

## 5. 控制期限、长休结算与续控扩展点

### 5.1 UI 选项与持久化档案

S2B 创建时，DM 必须明确选择以下之一，不设默认值：

| UI 名称 | 持久化 `durationKind` | 当前产品行为 |
| --- | --- | --- |
| **24 小时（按一次长休结算）** | `one-long-rest` | 战后候选中建立 `remainingLongRests: 1`；经 DM 接受后，控制者下一次登记的长休会使控制到期。 |
| **永久** | `permanent` | 成为正常的长期受控/召唤关联，不自动到期。仅表示 DM 裁定的产品状态，不宣称 `Animate Dead` 或 `Create Undead` 的法术控制永久有效。 |
| **自定义** | `rounds \| encounters \| long-rests` | DM 指定正整数 `N` 与计量单位：`N` 个完整回合、`N` 场完成的战斗，或 `N` 次登记的长休。计数归零时到期。 |

- “24 小时（按一次长休结算）”是本地产品的战役时间简化，必须在 UI 中明确标示；它不等同于规则书的精确时钟。
- 规则书中 `Animate Dead` 与 `Create Undead` 的已核验候选事实是“控制 24 小时、在到期前重施可延长控制”；条文没有使亡灵本体在到期时消失。本 Amendment 因此把默认到期结果固定为 `expired-uncontrolled`，而不是删除生物或无痕移除棋子。
- 需要跨战斗保存的 `one-long-rest`、`long-rests` 与 `permanent` 仅可在控制者有正式 CharacterSheet 关联且 DM 接受战后候选后生效。无长期角色卡的控制者只能维持本场会话内的控制状态，或由 DM 以明确事件处理。

### 5.2 计数、到期与未来续控接口

- `rounds`：从创建确认后的下一完整回合开始计数；第 `N` 个完整回合结束时追加到期事件。
- `encounters`：受控生物实际参与并完成一次战斗收口，才消耗一次；第 `N` 场收口后追加到期事件。
- `long-rests`：只在 DM 明确登记控制者完成一次长休时消耗一次；不得以现实时间、浏览器刷新或战斗结束自动扣减。
- 长休/自定义到期统一追加 `combatant.controller-link.expired`（或等效事件），将状态转为 `expired-uncontrolled`，关闭命令能力，并保留可追溯历史。
- 长休到期时，关联生物模块应出现“是否尝试通过施法续控？”提示。当前交付只允许记录 `renewal-requested` 审计意图；该意图**不得**阻止到期、恢复控制、消耗资源或声称已施法。
- 未来经单独规则准入后，该提示才可接入具体法术续控动作，并验证法术版本、资格、施法位、材料、目标上限、重施时机和规则效果。该后续工作已登记为 [BL-026 受控生物的法术续控与规则档案](../../docs/BACKLOG.md#bl-026-受控生物的法术续控与规则档案)，并依赖 BL-023；两者均不因本 Amendment 获得实施授权。

## 6. Schema、迁移、撤销与战后隔离

- 结构化 `controlledEntities` 超出 ABC 中仅记录 S2B `controllerLink` 的范围。实施前必须把 CharacterSheet Schema 从 `0.3.0-m1-s5` 提升为新的兼容版本，并为旧卡定义“缺失集合等于空集合”的只读兼容；不得批量改写现有角色卡。
- 只有 DM 接受战后候选时，才为控制者 CharacterSheet 创建包含受控生物关系的下一修订。拒绝、废除、角色卡已归档、修订不匹配、投影不匹配或关系记录不完整时，必须零写回。
- 跨战斗控制期限是新的持久化业务语义。实施前必须提升 Session Envelope Schema，并采用 copy-on-write 迁移：新 Schema 写入新的 v0.5.0 后继 key，旧 v0.5.0 key 与 v0.4.0 及更早 key 均只读保留；损坏或未知结构必须阻断恢复而非覆盖旧数据。
- 撤销继续使用补偿事件。创建受控生物、接受关系候选、登记长休、续控意图、到期、释放和失控都必须可审计；有后续依赖事件时不得无痕回退或删除历史。
- 战后候选只写入**控制者**的匹配 CharacterSheet，不写回尸体来源 PC/NPC 的 CharacterSheet。S2B 仍不得成为原 PC 的复活、后继卡或玩家控制权回归。

## 7. 必测项与明确非目标

### 必测项

- 四项死亡后处理入口无默认选择、无 Slice 代号；每项只显示自身面板和结果提示。
- S2A/S2B/S2C 的地图跳转、取消零写入、占格/多格/越界拒绝、空格原子提交，以及尸体占格拒绝。
- `controlledEntities` 与普通 `linkedEntities` 的独立存储、独立渲染和刷新恢复；无 CharacterSheet 的控制者不产生长期关联。
- 命令距离、控制状态、到期状态的提交 guard；到期后命令必须被拒绝，且生物不被自动删除或自动敌对。
- 24 小时（一次长休）候选默认不直接写入；接受后登记一次长休会准确到期。永久关系不被长休扣减；自定义三种计数边界均可恢复、可审计。
- `renewal-requested` 仅记录意图，不能续控；回归测试继续覆盖 S1、S2A、S2C、v0.4.0 冻结兼容与旧 key 零改写。
- CharacterSheet/Session 迁移、未知结构安全拒绝、候选修订隔离及补偿撤销边界。

### 明确非目标

- 不实施任何具体法术的施法、重施、法术位、材料、目标上限、升环、资格或自动合法性判断。
- 不建立完整 Campaign Time、真实时间计时器、长休自动推断或跨设备时间同步。
- 不把控制到期解释为亡灵死亡、消失或自动从地图删除；这类结果只能由独立 DM 事件或以后获准的效果合同处理。
- 不改变原 PC/NPC 死亡事实、原 CharacterSheet 边界、S2A/S2C 独立角色卡原则、S1 原实例复活，亦不授权任何生命周期后续门禁。
